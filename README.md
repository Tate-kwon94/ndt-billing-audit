# NDT Billing Audit

원전 배관 비파괴검사(NDT) 기성 청구를 **문서 근거로 검증하는** 도구입니다.
매월 수천 행의 청구서를 놓고 "이 검사는 도면이 요구한 것인가, 성적서가 뒷받침하는가"를 가립니다.

실제 프로젝트를 위해 만들었고 폐쇄망에서 운영합니다. 이 저장소는 **공개용으로 재구성한 것**이라
고객·계약·문서 식별자가 들어 있지 않습니다. 샘플과 픽스처는 형식만 실물과 같은 합성 데이터입니다.

## 문제

청구 한 행은 "이 용접부에 이 검사를 했으니 값을 달라"는 주장입니다. 검증하려면 서류 넷을 이어야 합니다.

```
청구서(행)  ──성적서번호──▶  검사 성적서  ──도면번호──▶  도면(검사 범위표)
     │                            │                         │
     └── 용접도 ──────────────────┘                    절차서(SCWEP)
```

전부 스캔 PDF이고, 도면은 수십 장, 성적서는 천 쪽이 넘습니다. 사람이 표본으로 훑는 것 말고는 방법이 없었습니다.

## 설계에서 지킨 것

**판정은 결정론이 한다. LLM은 설명과 추출만 한다.**
합격·불합격을 규칙이 정하고, LLM이 그 판정을 뒤집지 못하도록 상한을 둡니다.
LLM이 더 엄한 판정을 주장해도 결정론이 내린 것보다 위로 올라가지 못합니다.

**근거 없는 값은 틀린 값보다 위험하다.**
추출된 숫자가 그 쪽 원문에 실재하는지 대조합니다. 없으면 값을 비우고 재확인 표시를 붙입니다.
실제로 표를 못 읽은 상태에서 모델이 검사율을 그럴듯하게 채운 적이 있고, 그 값이 조용히 통과하면
"요구되지 않은 검사"가 "요구된 검사"로 뒤집힙니다. → `app/analyzers/extraction_guard.py`

**인용문은 원문과 대조한다.**
근거로 제시된 문장이 그 문서 그 쪽에 실제로 있는지 확인합니다. 문서·쪽이 맞아도 문장이 지어낸 것일 수 있습니다.
OCR 잡음을 견디도록 부분 유사도로 봅니다. → `verify_quote`, `app/analyzers/scwep_basis.py`

**"모른다"와 "틀렸다"를 구분한다.**
검증에 실패한 것과 검증할 수단이 없던 것은 다릅니다. 후자를 오답으로 처리하면 정당한 근거가
한꺼번에 무효가 됩니다. 판정을 바꾸지 않고 표시만 남깁니다.

**모호하면 고르지 않는다.**
후보가 둘 이상으로 좁혀지지 않으면 매칭을 확정하지 않습니다. 첫 후보를 집는 것은 추측입니다.

## 눈여겨볼 구현

| 파일 | 무엇 |
|---|---|
| `app/extractors/item_notation.py` | 청구서가 쓰는 압축 표기(`1.1÷6`, `(1÷65)X-1,2`, `A,B-up,dn`)를 실측으로 문법을 밝혀 해석. 펼친 개수를 청구 수량과 대조해 불일치를 잡는다 |
| `app/analyzers/extraction_guard.py` | 추출값의 원문 근거 검증. 같은 구조의 문서들이 서로 다른 값을 냈는지도 본다 |
| `app/analyzers/scwep_basis.py` | 절차서 근거로 면책을 인정하는 게이트. 인용문 검증과 조건 대조를 요구한다 |
| `app/extractors/table_pages.py` | 표 페이지만 골라 멀티모달로 전사하고 OCR 숫자와 대조 |
| `app/matchers/deterministic.py` | 규칙 순서대로 좁히되 하나로 좁혀질 때만 확정 |
| `app/table_bench.py` | 표 전사 정확도를 정답표로 채점. 열별로 세어 모델 오독과 문서 차이를 가른다 |
| `app/report/score_review.py` | 검토 결과를 정답표와 대조해 매칭·판정·판정불가 표시를 따로 채점 |

## 구조

```
app/analyzers/    판정·게이트·규칙 검증
app/extractors/   PDF·엑셀 추출, OCR, 표 전사
app/matchers/     청구↔성적서 매칭
app/report/       검토 엑셀, 채점, 라벨 시트
app/gui/          런처
ndt_3d/           도면 좌표 추출·오버레이
```

## 실행

```bash
pip install -r requirements.txt
pytest -q                                      # 612 passed

python scripts/make_synthetic_samples.py       # 합성 샘플 생성 (스캔 PDF·청구 엑셀)
NDT_HCX_MOCK=1 python scripts/demo.py          # 시연 — LLM 없이 결정론 경로만
python -m app.main --help
```

`make_synthetic_samples.py` 는 실물과 **형식만** 같은 문서를 만듭니다. 텍스트 레이어 없이
이미지로 렌더하므로 OCR·표 인식 경로가 실제로 돕니다. `demo.py` 는 청구서 파싱부터 근거 사슬까지
차례로 보여주는데, **OCR 이 성적서 표를 통째로 놓치는 장면까지 그대로 나옵니다.** 이 도구가
멀티모달 전사와 근거 검증을 붙인 이유가 그 화면에 있습니다.

LLM 호출은 OpenAI 호환 엔드포인트와 사내 전용 API 둘 다 지원하며, 주소와 토큰은 환경변수로 받습니다.
`NDT_HCX_MOCK=1` 이면 호출 없이 픽스처로 동작합니다.

## 만들면서 배운 것

- **입력이 비었는지 먼저 본다.** 모델이 이상한 답을 낼 때 프롬프트부터 고치려 들었지만,
  대부분 원인은 모델에 아무것도 안 들어간 것이었다.
- **채점기를 먼저 의심한다.** 모델 정확도가 87.5%로 나왔는데 실제로는 100%였다.
  정답표가 두 규격을 슬래시로 이어 적고 모델은 공백으로 이어 적은 차이였다.
- **테스트는 모양이 아니라 규칙을 고정한다.** 반환값의 정확한 dict 모양을 검사하면
  필드가 하나 늘 때마다 깨지고, 정작 회귀는 못 잡는다.
- **가짜는 전송 계층만 바꾼다.** 클라이언트 함수 전체를 가짜로 바꾸면 그 안의 기본값 채우기와
  재시도를 안 타서, 실환경에서만 죽는 결함이 테스트를 통과한다.
